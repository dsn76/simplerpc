# simplerpc (libsrpc)
- Статус - в разработке.
- Текущая версия 0.2.0

**simplerpc** — это легковесный и высокопроизводительный фреймворк для реализации удалённого вызова процедур (RPC) между процессами в операционной системе Linux, написанный на языке C. 

Проект предоставляет механизмы для прозрачного межпроцессного взаимодействия (IPC), используя разделяемую память (Shared Memory) и UNIX-сокеты, а также включает в себя собственные примитивы синхронизации на базе `futex` и эффективный аллокатор памяти.


## Краткое описание
Проект **simplerpc** (библиотека `libsrpc`) представляет собой высокопроизводительный фреймворк для организации удалённого вызова процедур (RPC) между различными процессами в среде Linux. 
Архитектура базируется на использовании разделяемой памяти (Shared Memory) для передачи данных и UNIX-сокетов для сигнального взаимодействия. Для управления памятью в разделяемых сегментах используется внешний аллокатор **TLSF** (Two-Level Segregated Fit), подключаемый через git-подмодуль. Синхронизация между потоками и процессами реализована через низкоуровневые примитивы Linux (`futex`), включая собственные реализации MPMC-очередей (Multi-Producer Multi-Consumer). Особенностью проекта является встроенный статический загрузчик (embedded loader), который компилируется и интегрируется в динамическую библиотеку `libsrpc.so` в виде C-массива с помощью утилиты `xxd`, что позволяет библиотеке самостоятельно инициализировать фоновые процессы (демоны).


## 📋 Основные возможности

- **Межпроцессный RPC:** Прозрачный вызов функций, реализованных в одном процессе, из адресного пространства другого процесса.
- **Разделяемая память (Shared Memory):** Использование общего участка памяти для высокоскоростного обмена данными без лишних копирований.
- **Аллокатор TLSF:** Интеграция аллокатора *Two-Level Segregated Fit* для быстрого и детерминированного выделения блоков в разделяемой памяти (`libsrpc_shmem_malloc`).
- **Синхронизация на базе Futex:** Собственные реализации очередей MPMC (Multi-Producer Multi-Consumer), мьютексов и условных переменных, оптимизированные для ядра Linux.
- **Встроенный загрузчик (Embedded Loader):** Наличие статически скомпилированного загрузчика, интегрированного в основную библиотеку, для автоматического развертывания фоновых процессов (демонов).
- **Асинхронность и очереди:** Поддержка асинхронной обработки запросов через внутренние очереди сообщений.

## 🛠 Технологический стек

- **Язык программирования:** C17
- **Система сборки:** CMake (версия 3.10+), Make
- **ОС:** Linux
- **Зависимости:**
  - Стандартные библиотеки: `pthread` (потоки), `dl` (динамическая загрузка).

## 📂 Структура проекта

```text
simplerpc/
├── CMakeLists.txt      # Основной файл конфигурации CMake
├── Makefile            # Вспомогательный Makefile для автоматизации сборки
├── src/                # Исходный код ядра библиотеки libsrpc
│   ├── libsrpc.c       # Основной API и логика RPC
│   ├── libsrpc_daemon.c# Логика работы демона/серверной части
│   ├── libsrpc_unix_socket.c # Транспортный уровень на базе UNIX-сокетов
│   ├── libsrpc_shmem.c # Управление разделяемой памятью
│   ├── libsrpc_futex.c # Примитивы синхронизации на базе futex
│   └── loader.c        # Исходный код встроенного загрузчика
├── libs/               # Сторонние зависимости (субмодули)
│   └── tlsf_txn/       # Аллокатор памяти TLSF
└── example/            # Демонстрационные приложения
    ├── app.c           # Пример RPC-клиента
    └── log.c           # Пример RPC-сервера (демона логирования)
```

## 🚀 Сборка и установка

Для корректной сборки проекта необходимо клонировать репозиторий вместе со всеми подмодулями.

### 1. Клонирование репозитория
```bash
git clone --recurse-submodules https://github.com/dsn76/simplerpc.git
cd simplerpc
```

### 2. Сборка проекта
В проекте предусмотрен `Makefile`, который автоматизирует инициализацию подмодулей и вызов CMake.

```bash
make all
```
*Данная команда выполнит обновление git-подмодулей, создаст директорию `build`, сконфигурирует проект с помощью CMake и скомпилирует динамическую библиотеку `libsrpc.so` и примеры.*

Для ручной сборки через CMake:
```bash
mkdir -p build && cd build
cmake ..
make
```

### Режимы сборки
В `CMakeLists.txt` поддерживаются два режима (переменная `BUILD_TYPE`):
- `release` (по умолчанию): оптимизация `-O3`.
- `debug`: отладочная информация `-O0 -ggdb3 -DDEBUG`.
- Также доступна опция `ENABLE_SANITIZER` для включения AddressSanitizer и UndefinedBehaviorSanitizer при отладке.

## 💡 Пример использования

В директории `example/` представлены два приложения, демонстрирующие взаимодействие клиента и сервера.

1. **Серверная часть (`log`)** — процесс, который предоставляет функцию `log_write()` для удалённого вызова и работает в фоновом режиме.
2. **Клиентская часть (`app`)** — процесс, который вызывает `log_write()`, передавая данные через RPC, даже если функция физически выполняется в адресном пространстве другого процесса.

**Запуск сервера (демона):**
```bash
./build/example/log
```

**Запуск клиента в отдельном терминале:**
```bash
./build/example/app
```
В процессе выполнения клиент выделит память в разделяемом пуле (`libsrpc_shmem_malloc`), запишет туда строку и инициирует RPC-выов функции логирования, которая выполнится в процессе `log`.
