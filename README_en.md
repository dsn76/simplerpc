**simplerpc** is a C library for remote procedure calls (RPC) between processes on a single Linux machine. A function declared in a shared list is called like an ordinary C function and runs in the process that defined it.

Arguments and results travel through shared memory that every process maps at the same virtual address. A pointer to a block in the common pool is therefore equally valid in any process, and the data behind it is not copied. The UNIX socket is used only for housekeeping: registration, handing out the memory descriptor, and detecting process death. The pool is managed by a transactional TLSF allocator that survives a process dying in the middle of an operation.

## Demonstration

Three terminals, three programs from `example/`:

```bash
./build/example/log    # terminal 1: executor of log_write()
./build/example/clc    # terminal 2: executor of calc_add()
./build/example/app    # terminal 3: caller
```

`app` calls `log_write(...)` and `calc_add(1, 2)` as ordinary functions. The string from `app` appears in the first terminal: the `log` process printed it. The sum was computed by the `clc` process. Argument serialization is generated by X-macros; nothing has to be written by hand. The executors are stopped with `./build/example/all_exit`.

To use the library in your own application:

1. Add the function prototype to the `RPC_LIST` X-macro in `src/libsrpc_rpc_functions.h`. This file is part of the library sources, not a separate application header.
2. Rebuild `libsrpc.so`.
3. Define the function in the executor process, and simply call it in the caller process.
4. Add `#include "libsrpc.h"` and link the application against `libsrpc.so` with `-Wl,--no-as-needed`.
5. After rebuilding the library, restart every process that uses it.

The coordinator daemon does not need to be started by hand: the first process that loads `libsrpc.so` brings it up. When the last client disconnects, the daemon exits on its own.

## 📋 Main Features

- **RPC as an ordinary call.** The linker chooses the role of a process: the one that defined a function is its executor, the one that did not is the caller. There is no IDL, no code generator, and no runtime registration.
- **Shared memory without copying the data.** The pool is mapped at one virtual address in every process. Only the arguments themselves are copied into an RPC request; the data behind pointers stays where it is.
- **Transactional TLSF allocator.** Allocation in O(1). A cross-process robust mutex and a BUL (Binary Undo Log) rollback journal: if a process dies in the middle of `malloc` or `free`, the next one to take the mutex rolls the unfinished operation back.
- **Memory ownership model.** Every block is tagged with the UIDs of its owner processes, up to 12 per block. `libsrpc_shmem_link()` adds an owner, `libsrpc_shmem_free()` removes only the caller's. A block can thus be handed to another process without copying.
- **Cleanup after dead processes.** The daemon learns of a client's death immediately, from the socket disconnect, and returns its blocks to the pool. The caller can temporarily hold an executor's blocks with `libsrpc_shmem_proc_lock()`: they then survive its death until the hold is released.
- **Garbage collector.** A thread in the daemon frees service blocks that other processes might still have been reading. Occupancy is checked through Hazard Pointers.
- **Dispatch.** A call can be executed by every registered executor (`RPC_SEND_ALL`), the first one (`RPC_SEND_FIRST`), the last one (`RPC_SEND_LAST`), or one in round-robin (`RPC_SEND_RR`). The replies of all executors are available through `libsrpc_lastreq_num()` / `libsrpc_lastreq_get()`.
- **Queues and synchronization.** Each process has its own lock-free MPMC queue of incoming requests. Executor threads sleep on POSIX semaphores in shared memory.
- **Daemon with no file on disk.** The daemon executable is embedded in `libsrpc.so` and started from a `memfd` via `fexecve()`.
- **Allocator substitution (optional).** Interception of `malloc`/`calloc`/`realloc`/`free` with a per-thread switch to the common pool. Disabled by default, see `DISABLE_ALLOC`.

## 🛠 Requirements

- **OS and architecture:** Linux on x86_64. The kernel must support `MAP_FIXED_NOREPLACE` (4.17+). The code uses `memfd_create`, `fexecve`, abstract UNIX sockets, and `MADV_DONTFORK`. It also uses x86 instructions (`pause`) and the `-mrdrnd` flag.
- **Language:** C17.
- **Build:** CMake 3.10+, Make, `gcc` (the embedded loader is always built with `gcc`, regardless of the chosen compiler), and the `xxd` utility.
- **Libraries:** only the system `pthread` and `dl`. There are no external dependencies and no git submodules; the `tlsf_txn` allocator lives in the project tree.

## 🚀 Build

```bash
git clone https://github.com/dsn76/simplerpc.git
cd simplerpc
make all
```

`make all` creates the `build` directory, configures the project with CMake, and builds the static allocator library `libtlsf.a`, `libsrpc.so`, the examples, and the benchmarks. `make clean` removes `build`.

Manual build:

```bash
mkdir -p build && cd build
cmake ..
make
```

### Modes and Parameters

The mode is set by the `BUILD_TYPE` variable:
- `release` (default) — `-O3`;
- `debug` — `-O0 -ggdb3 -DDEBUG`, enables the verbose `DBG_PRINT` output.

| Parameter | Default | Purpose |
|---|---|---|
| `BUILD_TYPE` | `release` | Build mode: `debug` / `release` |
| `ENABLE_SANITIZER` | `OFF` | AddressSanitizer + UndefinedBehaviorSanitizer (`debug` only) |
| `DISABLE_ALLOC` | `ON` | Do not build the `malloc`/`calloc`/`realloc`/`free` substitution |
| `DBG_LVL` | `2` | Message level: `0` — off, `1` — ERR, `2` — ERR+WRN, `3` — ERR+WRN+INF |
| `MPMCQ_DEGREE` | `10` | Per-process request queue capacity as a power of two (`2^10 = 1024`) |
| `SHMEM_SIZE_KB` | `4096` | Shared-memory pool size, KiB |
| `SHMEM_BASE_VADR` | `0x200000000000` | Virtual address at which the pool is mapped in every process |

```bash
cmake -DBUILD_TYPE=debug -DDBG_LVL=3 -DSHMEM_SIZE_KB=16384 ..
```

> **Important:** every CMake configuration (including every `make all`) stamps a new `BUILD_TS` timestamp into the library. The daemon name, the socket name, and the pool signature are derived from it. Processes that loaded different builds of `libsrpc.so` cannot see each other: this protects against a diverging `RPC_LIST`. After a rebuild, every process must be restarted.

`ERR` and `WRN` messages go to the process's `stderr`. The daemon inherits the `stdout`/`stderr` of the process that started it, so its messages appear in that process's terminal.

## 💡 Usage

### Declaring an RPC Function

Every remotely callable function is listed in a single X-macro, `src/libsrpc_rpc_functions.h`. It currently holds the example functions:

```c
#define RPC_LIST    \
    XF(RPC_SEND_ALL, int,    testlocal) \
    XF(RPC_SEND_ALL, pid_t,  log_write, const char*) \
    XF(RPC_SEND_ALL, int,    calc_add, int, int) \
    XF(RPC_SEND_ALL, void,   all_exit) \
    XF(RPC_SEND_ALL, void *, list_api, int, void *) \
```

Entry format: `XF(dispatch policy, return type, name, parameter types...)`.

- **Policies.** `RPC_SEND_ALL` — to every executor. `RPC_SEND_FIRST` — to the first available one in the registry. `RPC_SEND_LAST` — to the last one in the registry. `RPC_SEND_RR` — to one, round-robin.
- **Types.** Arguments and the result are copied byte by byte, so scalar types and pointers are allowed. A pointer is meaningful only if it points into the shared pool. Functions with a variable number of arguments are not supported.
- **Type visibility.** Types must be declared before `RPC_LIST`: `libsrpc.h` includes `<stdint.h>` and `<sys/types.h>`; your own types must be included from `libsrpc_rpc_functions.h`.
- **Identifiers.** Each function gets a generated `libsrpc_funid_<name>`, used by `libsrpc_timeout_func_set()` and `libsrpc_fnreg_num_get()`.

### Who Is the Executor and Who Is the Caller

There is no separate server API. A process that **defined** a function from `RPC_LIST` becomes its **executor**: the application's strong symbol overrides the weak stub symbol from `libsrpc.so`. Calling that function inside the process itself is an ordinary local call. A process that did not define the function lands in the stub on a call, and the stub sends an RPC request. The role is chosen per function: one process can execute some functions and call others.

```c
/* Executor: defines the function. */
pid_t log_write(const char *msg) {
    fprintf(stderr, "LOG: '%s'\n", msg);
    return getpid();
}
```

```c
/* Caller: just calls. */
char *str = libsrpc_shmem_malloc(1024);          /* the string must live in the pool */
snprintf(str, 1024, "Hello from pid=%d", getpid());

pid_t pid = log_write(str);                      /* result of the first executor */
if (libsrpc_errno_get() != 0) { /* the call was not sent */ }

/* Results from all executors (RPC_SEND_ALL): */
for (int i = 0, num = libsrpc_lastreq_num(); i < num; i++) {
    int rc = libsrpc_lastreq_get(i, &pid, sizeof(pid));
    if (rc == 0) printf("pid[%d]=%d\n", i, pid);
    else         printf("slot %d: %s\n", i, libsrpc_strerror(-rc));
}
libsrpc_shmem_free(str);
```

Executor threads cannot make RPC calls themselves: the request is not sent, and `libsrpc_errno_get()` returns a non-zero code (`ERECURSIVE`). The other threads of an executor process, including the main thread, make RPC calls as usual.

### Call Result and Errors

The generated wrapper returns the result of the first response slot. If there is no response, the zero value of the type is returned (`0`, `NULL`). A zero result does not by itself distinguish an error from success, so the state of a call is checked in two ways:

- `libsrpc_errno_get()` — why the call **was not sent**: `ENOREGFUN` (no executors), `ERPCDISABLE` (no connection to the daemon), `ERECURSIVE`, `ENOTAVAILABLE` (no executor accepted the request), `ENOMEM`, `ESHMNOINIT`. The code is positive, and the wrapper clears it at the start of every call.
- `libsrpc_lastreq_get(i, ...)` — the fate of the **sent** request in slot `i`: `0` — a reply was received, `-ERPCWAITIMEDOUT` — the executor did not reply in time, `-ECANCELLED` — the executor disconnected without taking the request, `-ENOMEM` — the executor's queue is full. Timeout and cancellation do not show up in `libsrpc_errno_get()`.

A call succeeded when `libsrpc_errno_get() == 0` and the wanted slot returned `0`. Both conditions must be checked. If a call was not sent, the slot may still hold the reply of the **previous** call from the same thread. For functions that return a value, the reason for not sending is sometimes replaced by `ETIMEDOUT`, but a non-zero code remains a reliable sign of failure.

Codes above 4095 are libsrpc's own codes (listed in `src/libsrpc_errno.h`); the rest are system `errno`. `libsrpc_strerror(code)` returns the string for a code.

### Memory for Arguments

Everything passed through a pointer must live in the pool: `libsrpc_shmem_malloc()`, `libsrpc_shmem_calloc()`, `libsrpc_shmem_realloc()`. A block belongs to the process that allocated it. `libsrpc_shmem_free()` removes only the current process as an owner, and the block returns to the pool when no owners remain. If a process exits without freeing its blocks, the daemon frees them.

For a block to outlive its creator, the recipient calls `libsrpc_shmem_link(ptr)` and becomes the second owner, after which the creator may call `free`. Ownership thus moves to another process without copying the data: the `list` example demonstrates this.

The pool size is fixed at build time (`SHMEM_SIZE_KB`, 4 MiB by default) and does not grow at runtime.

### Timeouts

Waiting for a reply is bounded by a timeout in microseconds:

- `libsrpc_timeout_oneshot_set(us)` — for the next call in the current thread;
- `libsrpc_timeout_func_set(libsrpc_funid_<name>, us)` — for a function, in the current thread;
- `libsrpc_timeout_global_set(us)` — for all calls of all threads of the process.

Priority follows the order of the list. The default timeout is 1 s, and less than 100 µs cannot be set. The interval is counted again after every reply that arrives, so when dispatching to several executors the total wait can exceed the configured value.

### Linking

A process that only executes functions and never calls anything from `libsrpc.so` must be linked with `-Wl,--no-as-needed`. Otherwise the linker drops the dependency on the library, its constructor never runs, and the process never connects to the daemon. The examples and benchmarks are always linked with this flag.

The library constructor waits for the connection to the daemon before entering `main()`. By the time `main()` starts, the process is already registered and accepting requests.

## 📖 Public API

All declarations are in `src/libsrpc.h`. The results of the last call, error codes, the one-shot timeout, per-function timeouts, and holds belong to the current thread.

**Pool memory**

- `void *libsrpc_shmem_malloc(size_t size)`, `void *libsrpc_shmem_calloc(size_t num, size_t size)` — allocate a block; the owner is the current process. `NULL` on error.
- `void *libsrpc_shmem_realloc(void *ptr, size_t newsize)` — resize a block. Works only when the current process is the block's sole owner, otherwise `NULL`.
- `void libsrpc_shmem_free(void *ptr)` — drop the current process's ownership. The block returns to the pool together with its last owner.
- `int libsrpc_shmem_link(void *ptr)` — add the current process as an owner (no more than 12). Returns `0` or a negative code.
- `int libsrpc_shmem_get_size(void *ptr, size_t *psz)` — write the block's payload size to `*psz`. Returns `0` on success.

Memory functions report errors with the allocator codes `TLSF_ERR_*` (1…15, `libs/tlsf_txn/tlsf_txn.h`), and the same codes end up in `libsrpc_errno_get()`. These numbers overlap the system `errno`, so they must be decoded with `tlsf_strerror()`, not `libsrpc_strerror()`.

**Results of the last call**

- `int libsrpc_lastreq_num(void)` — number of response slots of the current thread's last RPC call (`0` if there were no calls).
- `int libsrpc_lastreq_get(int idx, void *retval, size_t sz)` — copy the result of slot `idx` into `retval`. `sz` must match the size of the return type exactly, `0` for `void`, otherwise `-EBADMSG` is returned. Returns `0` or the slot's negative code.

**Holding an executor's memory**

- `int libsrpc_shmem_proc_lock(int idx, void *ptr)` — hold the UID of the executor from slot `idx` of the last call, if the block `ptr` belongs to that executor. While the hold is in effect, the executor's death does not return its user blocks to the pool. Returns the hold slot number (`0…3`) or a negative code: `-ENOTFOUND` (the block is not its), `-EPROCDESTROYED` (the executor has already disconnected), `-ENOMEM` (all four slots are taken), `-EINVALREQUEST` / `-EINVALRESPONSE` / `-ENOTAVAILABLE` (no suitable call or slot).
- `int libsrpc_shmem_proc_unlock(int slot)` — release one hold. `int libsrpc_shmem_proc_all_unlock(void)` — release all holds of the thread.

Only the thread that took a hold can release it. Later RPC calls of that thread do not clear the hold. When the holder thread or process exits, the hold disappears on its own.

**Registry and timeouts**

- `int libsrpc_fnreg_num_get(libsrpc_funid_t funid)` — number of registered executors of a function; `-EINVAL` for a bad `funid`.
- `libsrpc_timeout_oneshot_set()`, `libsrpc_timeout_func_set()`, `libsrpc_timeout_global_set()` — see Timeouts.

**Errors**

- `int libsrpc_errno_get(void)` — the current thread's last error code.
- `const char *libsrpc_strerror(int code)` — the string for a positive code, either a system code or a libsrpc code.

**Allocator substitution** (only when built with `-DDISABLE_ALLOC=OFF`)

- `libsrpc_alloc_sw_shm()` / `libsrpc_alloc_sw_std()` — switch the current thread's `malloc`/`calloc`/`realloc`/`free` to the pool and back.

## ▶️ Examples

All examples are built into `build/example/`. Executors run until they receive `all_exit()`.

| Program | Role |
|---|---|
| `log` | Executor of `log_write()` and `all_exit()` |
| `clc` | Executor of `calc_add()` and `all_exit()`; itself calls `log_write()` |
| `app` | Caller: `log_write()` and `calc_add()`. Calls its own `testlocal()` locally |
| `all_exit` | Broadcasts `all_exit()`: stops `log`, `clc`, and `list_db` |
| `list_db` | Holds the shared list, executor of `list_api()` and `all_exit()` |
| `list_cli` | List client: `--add`, `--del`, `--print` |

```bash
./build/example/log         # terminal 1
./build/example/clc         # terminal 2
./build/example/app         # terminal 3
./build/example/all_exit    # stop
```

`app` allocates a string in the pool and calls `log_write()`: the string is printed in the `log` terminal. Then `calc_add(1, 2)` is computed in the `clc` process. If `clc` is not running, the call returns `0` and `libsrpc_errno_get()` returns `ENOREGFUN`.

### The list example: a shared list and ownership transfer

The example in `example/list/` shows the memory ownership model on a doubly linked list of strings that lives in the pool and is accessible to several processes.

**Roles.** `list_db` defines `list_api(int op, void *node)` and becomes its executor. `list_cli` does not define the function, so its call goes to `list_db` over RPC. Operations:
- `DAL_LIST_OP_GET_HEAD` — return the pointer to the list head;
- `DAL_LIST_OP_INSERT` — insert a node;
- `DAL_LIST_OP_REMOVE` — remove a node.

**Starting `list_db`.** `libsrpc_fnreg_num_get(libsrpc_funid_list_api)` checks whether another executor of `list_api()` already exists. If it does, the second instance exits: the example has one list. The list head is then allocated in the pool, and a robust mutex with `PTHREAD_PROCESS_SHARED` is initialized in it. Through this mutex the processes agree on who currently changes or reads the list links. The head belongs to `list_db`, because it allocated it.

**Adding (`--add`) — transferring ownership.**

```c
list_cli_node_t *node = libsrpc_shmem_malloc(sizeof(*node) + len + 1);
/* fill in size and data */
void *ptr = list_api(DAL_LIST_OP_INSERT, node);
libsrpc_shmem_free(node);
```

`list_cli` allocates a node and passes the pointer to `list_api()`. In `list_db` the insertion starts with `libsrpc_shmem_link(node)`: the node now has two owners. The node is then inserted into the list under the mutex. Back from the call, `list_cli` calls `libsrpc_shmem_free(node)`. This removes only its UID, and the node stays in the list, now belonging to `list_db` alone. Exiting `list_cli` no longer affects the list.

**Printing (`--print`) — holding the executor's memory.** `list_cli` obtains the head with `list_api(DAL_LIST_OP_GET_HEAD, NULL)` and immediately calls `libsrpc_shmem_proc_lock(0, list_head)`. The library checks that the head belongs to the executor from slot 0 and holds its UID. While the hold is in effect, a sudden death of `list_db` returns neither the head nor the nodes handed to it to the pool. `list_cli` then takes the mutex, walks the list, prints the strings, releases the mutex, and drops the hold with `libsrpc_shmem_proc_unlock()`.

**Deleting (`--del`).** The string is found in the same order: head, hold, mutex, walk. The found node is passed to `list_api(DAL_LIST_OP_REMOVE, node)`. In `list_db` the node is unlinked and freed with `libsrpc_shmem_free()`. By then `list_db` is the sole owner, so the block returns to the pool.

```bash
./build/example/list_db                                   # terminal 1
./build/example/list_cli --add hello --add world --print  # terminal 2
size: 30, data: world
size: 30, data: hello
./build/example/list_cli --del hello --print
size: 30, data: world
./build/example/all_exit
```

Nodes are inserted at the head of the list, so they print in reverse order. `size` is the size of the whole node, header included. The example is a teaching one: recovering the list mutex after `EOWNERDEAD` is not implemented in it.

## 📈 Performance Measurements

```bash
make all
./bench/run_bench.sh build 4000 4    # build directory, iterations, thread count
```

The script starts an executor, runs the baselines (`pipe`, `socketpair`), then a single-threaded and a multi-threaded RPC round trip. It prints the latency distribution (min/p50/p90/p99/max) and the throughput.

## ⚠️ Limitations

- Linux x86_64 only, and only processes on one machine.
- Every process must load the same build of `libsrpc.so`. `RPC_LIST` is compiled into the library, so changing the function list requires rebuilding it and restarting every process.
- The daemon is a single point of failure. If it dies, RPC in the already running processes is disabled and does not recover on its own. New processes bring up a new daemon with a new pool and do not see the old ones.
- Client credentials are not checked. Any process that connects to the daemon's abstract socket gets access to the whole pool. The library is not meant for processes that do not trust each other.
- Every process that loaded the library, even a caller-only one, starts executor threads, one per CPU. After every request they spin briefly before sleeping.
- The timeout is counted from the last reply that arrived, not from the start of the call.
- The pool size is fixed at build time.
